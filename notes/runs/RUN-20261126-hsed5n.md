## Notes
What in `crates/node` belongs to the process or to the machine rather than to one node
(`survey.txt`, read by hand; the tests' own paths are among the hits and were set aside):

- **Process-wide statics:** two, both in `link.rs:130`: `VIA_TAILNET` (whether the hub is
  dialled through a tailnet identity) and `TAILNET` (the identity, a `OnceLock`). Every node in
  the process reads them; [[RUN-20261126-hseepp]] shows what that does.
- **Environment written:** none. No `set_var`, `remove_var` or `set_current_dir`.
- **Environment read:** `HOME` for the defaults below, photo uploads (`link.rs:494`) and `~` in
  profiles; `XDG_RUNTIME_DIR` for the wrapper socket and the shell holder's; `SHELL` for the
  spawner's login shell. Read, never written, so per-process, not per-node, but harmless.
- **Machine-wide defaults** (all per user, all overridable by a flag of `node serve`): the
  wrapper socket `$XDG_RUNTIME_DIR|user temp/saarthi-<uid>/node.sock`, the changes socket and
  the sandbox hook socket under `~/.local/state/saarthi/`, the shell holder's socket, the
  tailnet state `~/.local/state/saarthi/tailnet`, the hook port `127.0.0.1:7777`. Photo
  uploads go under `~/.local/state/saarthi/uploads/<session>` (`uploads.rs:19`, no flag, but
  per session). The Claude API sockets share one directory with a random name each
  (`claude_api.rs:79`), so they do not collide.
- **Signals and the log subscriber:** only in `main.rs` (`ctrl_c`, `tracing_subscriber::fmt`).
  The library installs neither.
- **The registry scan** is in `main.rs` too (`scan_registry`), over the node's Claude dir and
  its profiles' dirs: a node assembled from the library scans only if its builder does.
- `serve` itself is a 360-line function in `main.rs`; the library exports the parts, and the
  hub's tests assemble a node from them (`crates/hub/tests/common/mod.rs`), as run 3 does.

Ran before the spike was committed, on files identical to `commit` (8637e4a adds the scripts unchanged; `crates/` is the same at both).
