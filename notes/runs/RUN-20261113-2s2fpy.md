## Notes
On rogue, no sandbox, Claude Code 2.1.322, the owner's sandbox setup-token. `proxy.py`
listened on a unix socket and replaced the `Authorization` header; a logging CONNECT proxy
as `HTTPS_PROXY` named what went direct.

- `ANTHROPIC_UNIX_SOCKET` alone: Claude Code speaks TLS over the socket (a stub answering
  HTTP saw garbage; claude reported `EPROTO`). It uses the socket as a raw transport.
- With `ANTHROPIC_BASE_URL=http://api.anthropic.com` as well: plain HTTP/1.1 over the
  socket, `POST /v1/messages?beta=true`, `Host: api.anthropic.com`, the token as
  `Authorization: Bearer <dummy>`, the `oauth-2025-04-20` beta, no `x-api-key`.
- Through the proxy: a turn (`pong`) and its resume (`Pong.`) ran with only the dummy in
  claude's environment; both `/v1/messages` calls went through the socket, 200. Eight
  CONNECTs per run still went straight to `api.anthropic.com:443`.
- `--debug` names some of them: remote settings, policy limits and an OAuth account check
  get 401 with the dummy (with the real token: settings 404, policy limits fetched, the
  account lookup skipped for want of the profile scope). The model is the same either way.
- A first proxy version waited for the answer before relaying the rest of a 58 KB request
  body and the API reset the connection; fixed before the recorded run.
