## Notes
`probe.c` against libghostty-vt 1.4.0 built for this Mac (aarch64-darwin) from the flake's
new `libghostty-vt` package, 80x24, 10,000 lines of scrollback. The final run
(`probe.log`): 9,613 scrollback rows kept of 12,000 lines written (the line cap prunes by
page); the screen with its scrollback and a styled prompt restored exactly, cursor
included, 314 KB of VT formatted in about 3 ms; the alternate screen restored exactly;
leaving it, the primary screen, its scrollback and its cursor came back the same. The
library also built for x86_64-linux on the remote builder; the probe itself ran only here.

Four things found on the way, each now in the probe:
- The terminal also caps scrollback by bytes, and that cap came first: about 770 lines
  were kept until `SCROLLBACK_MAX_BYTES` was set to none.
- The formatter writes the active screen only. Reaching the primary screen under a
  full-screen program by switching the source with mode 47 left mode 47 set on it, so a
  later snapshot would put the client in the alternate screen: the source must not be
  changed to read it.
- Instead the holder formats the primary screen, with its scrollback, just before writing
  a sequence that enters the alternate screen (`CSI ?1049h`, `?1047h`, `?47h`), and keeps
  it; the primary screen cannot change while the alternate one is shown. The snapshot is
  then that, followed by the alternate screen with its modes, which take the client into
  it and save the cursor for its return.
- A screen formatted with its modes while 1049 is set starts with `CSI ?1049h`; the
  kept primary is formatted before the switch, so it never carries one.
