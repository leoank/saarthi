## Notes
The spike app (`spikes/14-service-relay/webview`, a plain `WebView` activity) on the rc2s2
emulator (arm64, Android System WebView 124.0.6367.219), against the relay and `yajna serve`
of [[RUN-20261114-rn027z]] on this laptop. A test page (`/__sse.html`, served by the
relay's proxy) logs each change event's arrival by the device clock; the host appends to
the watched file and stamps each write. Two ways of feeding the WebView:

- **loopback**: the WebView loads the proxy's port, as it would a port the core serves on
  the phone. All ten writes arrived as events, each on its own, about 1 s apart like the
  writes: 139 ms after the write by the device clock, which ran 91 ms behind the laptop's,
  so about 230 ms, the same as yajna's own watching on the laptop (263 ms).
- **intercept**: `shouldInterceptRequest` answers with a `WebResourceResponse` over an
  `InputStream` (an HTTP connection to the same proxy, standing in for the core's stream).
  The stream was intercepted (200, `text/event-stream`) and **no event of the ten reached
  the page**. With 200 writes 0.1 s apart, 80 events arrived in 9 bursts, the first 6 s
  after the first write: the WebView reads an intercepted body in large blocks and hands it
  to the page only when a block is full. A long-lived stream cannot go through
  `shouldInterceptRequest`.

So H2 is false: the core has to serve the relay on a loopback port of the phone, and the
WebView load from it. Any app on the phone can reach a loopback port, so that port must
demand a secret the app gives only its WebView (a per-start token in the path or a cookie).

The files viewer (`/files/`) loads both ways (10 requests intercepted), but only with DOM
storage on: with the WebView's default (`domStorageEnabled` false) it rendered blank with
no console error. At phone width its tree pane shows nothing; the viewer is laid out for a
desktop, a matter for yajna's frontend, not the relay. Screens in `files-*.png` (a scratch
notebook, nothing private).

Earlier attempts in the same session are not counted: the first watched a stale
`yajna serve` left on the port by [[RUN-20261114-rn027z]]'s script (fixed there with
`exec`), the second had no DOM storage and an emulator clock 361 ms off.
