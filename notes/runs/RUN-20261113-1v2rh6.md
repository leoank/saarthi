## Notes
aarch64-darwin, libtailscale `ac7ed43` at the working tree of `e615a63` (the changes were
not yet committed), the arm64 Android 15 emulator `rc2s2` with no Tailscale app, the
scratch hub of [[EXP-20261112-rq8kgc]] serving on the owner's tailnet as
`saarthi-try-hub`, the owner's reusable, pre-approved, non-ephemeral test key. Done by
hand step by step; `run.sh` repeats the steps in one go.

1. `-buildmode=c-archive` for `android/arm64`: Go refuses ("not supported on
   android/arm64"). `c-shared` builds once the stdenv's `CC` and macOS SDK variables are
   replaced by the NDK's clang inside the build phase: an arm64 ELF needing only
   `liblog`, `libdl` and `libc`, 30 MB, 22 MB stripped. The core links it as `NEEDED
   libtailscale.so` and the app loads both from `jniLibs`.
2. In the app, `tailscale_up` failed at once: `tsnet.Up: tsnet: route ip+net: netlinkrib:
   permission denied`, with SELinux denying `bind` on `netlink_route_socket` for
   `untrusted_app`. As predicted.
3. With a netmon interface getter on `getifaddrs` added to the build: the identity joined
   (state written), then the process aborted in Go: `panic: no safe place found to store
   log state`, from `logpolicy.LogsDir`, which on Android finds no systemd directory,
   HOME, cache or writable temp directory.
4. With `TS_LOGS_DIR` set through an exported setter before the start: the app joined as
   `saarthi-sdk-gphone64-arm64` and reached `http://saarthi-try-hub:7700`, a name only
   the tailnet resolves, and listed the hub's node.
5. Cold start from the saved state, no key needed by tsnet: the boot log showed `Joined
   tailnet as saarthi-sdk-gphone64-arm64 (…, 161 ms)` and `Connected to hub try-tailnet
   at http://saarthi-try-hub:7700 (746 ms)`, then the node and `Reached target Sessions.`
   (the capture shows the tailnet addresses, so it is not kept).

Also seen: the scratch hub, started from its saved state with no key, printed a login URL
every five seconds and never came up: the tailnet had logged its identity out, and the
hub read the key file only when no state existed. Read on every start, the same key file
brought it back.
